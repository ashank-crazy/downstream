How it works

Downstream sits in every team's room through Switch. Each room has a contract, a few lines saying what it owns and what it depends on. Think CODEOWNERS for conversations.

Knows who depends on what

Reads each room's contract from its Switch instructions. Teams edit it by talking to it: we depend on payments webhook.

Notices changes, stays quiet otherwise

A message must say something changes and name something another room depends on. Questions and small talk get no reply.

The author decides

It asks in the author's own thread first. send, send billing or skip. It never posts into another team's room on its own.

Briefs each affected room

The original message, who said it, and exactly why this room is getting it.

Relays both ways

Questions in a briefed room's thread show up in the author's thread, and answers go back. Nobody has to join anyone else's channel.

Chases, then closes the loop

ack and not us are tracked per room. Quiet rooms get reminders. When everyone has answered, the ripple closes and a ledger document records it.

In the author's thread

Within a second of the announcement, before anyone else hears about it.

Why it needs Switch

Downstream isn't a chatbot bolted onto one channel. It works because Switch makes one agent a member of many rooms, shared by people and other agents, across whatever chat app a team uses. Take Switch away and nothing is left.

Switch primitiveWhat Downstream does with it
scope=all event streamOne connection hears every room Downstream belongs to, so changes are noticed where they're said, without anyone mentioning the bot.
Session placementsOne placed session per room on that single connection, so every reply and document write lands in the right room.
ThreadsProposals, briefings, relays and reminders all live in threads, so channels stay readable.
Targeted messagesProposals address the author; briefings address the room's people, so they get real notifications.
Room instructionsThe first source for a room's contract.
Room documentsdownstream-contract and downstream-ledger in every room, readable by every person and agent there.
Linked roomsEach delivered ripple links the source room to the affected room.
create_room & templatesSeeds the demo org; a room template creates contract-carrying team rooms from Switch Console.
Kickoffs & addressingAnswers template kickoffs as the person they were posted for; opens itself to everyone, because a teammate every team talks to can't be owner-only.
Collaboration bridgesNothing in Downstream knows it's on Mattermost: it only talks to Switch, so the same agent is meant to run in Slack, Teams, Discord or Telegram rooms. Built and tested on Mattermost.

Run it

Everything runs on one laptop: Switch's own standalone compose (Postgres, switch-core, Gateway, bundled Mattermost), pinned to 0.31.0. You need Docker, uv and Python 3.11+. No API key.

# 1. Switch, locally
git clone https://github.com/ashank-crazy/downstream && cd downstream
cp stack/.env.example stack/.env && bash stack/generate-env-secrets.sh stack/.env downstream
cd stack && docker compose --env-file .env -p downstream --profile collab --profile gateway up -d && cd ..

# 2. Downstream
uv sync
uv run downstream register     # registers @downstream and opens it to everyone
uv run downstream seed         # 5 demo people + 5 team rooms with contracts
DOWNSTREAM_NUDGE_SECONDS=45 uv run downstream run

# 3. Open http://localhost:8065 as admin, then in another terminal:
uv run downstream play         # plays the demo conversation (~80 s)

Optional: set ANTHROPIC_API_KEY and uv sync --extra claude to let Claude decide which rooms are semantically affected. Without it, a deterministic rules engine explains every decision in one line. Full details in the README.
